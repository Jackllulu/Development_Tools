# 内容规范（Content Standards）

规范工具条目的写作与可选元数据，保证目录在 GitHub 上可浏览、可审阅、可复制运行。

---

## 1. 语言

- **默认中文**撰写 `README.md`、`analysis.md`、`usage.md`、`links.md` 中的说明性文字。
- 命令、API、配置键、官方产品名保持原文（如 `npm install`、`pyproject.toml`）。
- 文件名、目录名、`id`（若有）使用英文 kebab-case。

## 2. 必备与推荐文件

| 文件 | stub 最低要求 | ready 要求 |
|------|---------------|------------|
| `README.md` | 2–4 句摘要 + 指向其余文件；标明 status | 含「适用场景」与「不适合」各至少一点 |
| `links.md` | 至少官方主页或仓库之一 | 分类清晰（官方 / 社区 / 相关） |
| `demo/README.md`（或 `examples/`） | 说明样例状态 | 可复现步骤，或明确「仅示意 / 复制用片段」 |
| `analysis.md` / `usage.md` | 可省略或「待补充」 | 有定位/对比或安装与常用流程（内容也可并入 README） |
| `meta.yaml` | **可选**；有则最小字段有效 | 链接可访问、与路径一致 |

## 3. 可选元数据

- GitHub 浏览不依赖 YAML；信息优先写在 `README.md`。
- 若提供 `meta.yaml`：`id` 与目录名一致；`dimension` / `group` 与路径一致；`updated` 为 `YYYY-MM-DD`。
- `status`：`stub` | `draft` | `ready`（也可只写在 README）。
- 不要把长文塞进 YAML；摘要控制在一两句。

## 4. 写作边界

- **摘要优先**：指向官方文档，不整章搬运。
- **可验证**：用法与演示中的命令应在合理环境下可执行（版本在文中注明）。
- **中立**：对比时写适用边界，避免无依据的绝对排名。
- **安全**：不收录用于未授权访问、恶意利用的「工具教程」；安全研究类条目保持防御与合法语境。

## 5. 实现样例（demo/ 或 examples/）

- 优先最小可运行示例或可复制粘贴片段；其次截图/录屏 + 步骤。
- 依赖使用常见包管理器；锁定或注明主版本。
- 不提交密钥、令牌、个人数据。
- 大媒体文件优先外链，并在 `demo/README.md` 写明来源。
- 样例留在工具目录内，不单独做成对外站点页面。

## 6. 审阅清单（PR 自检）

- [ ] 路径落在 `languages` / `frameworks` / `domains` 之一
- [ ] `README.md` 可读；若有 `meta.yaml` 则必填齐全且与路径一致
- [ ] 中文说明通顺；术语首次出现可附原文
- [ ] 外链非明显失效
- [ ] `demo/`（若有）说明如何运行或复制
- [ ] 未引入无关大文件或二进制垃圾
- [ ] 未引入独立站点脚手架作为本条目交付物
