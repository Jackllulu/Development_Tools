# 内容规范（Content Standards）

规范工具条目的写作与元数据，保证目录可在 GitHub 上检索、审阅与浏览。

---

## 1. 语言

- **默认中文**撰写 `README.md`、`analysis.md`、`usage.md`、`links.md` 中的说明性文字。
- 命令、API、配置键、官方产品名保持原文（如 `npm install`、`pyproject.toml`）。
- 文件名、目录名、`id` 使用英文 kebab-case。

## 2. 必备文件

| 文件 | stub 最低要求 | ready 要求 |
|------|---------------|------------|
| `meta.yaml` | 全部最小字段有效 | 链接可访问、标签合理 |
| `README.md` | 2–4 句摘要 + 指向其余文件 | 含「适用场景」与「不适合」各至少一点 |
| `analysis.md` | 可放「待补充」标题 | 有定位、优缺点或对比小节 |
| `usage.md` | 可放「待补充」 | 有安装与至少一条常用流程 |
| `links.md` | 至少官方主页或仓库之一 | 分类清晰（官方 / 社区 / 相关） |
| `demo/README.md` | 说明演示状态 | 可复现步骤或明确「仅示意」 |

## 3. 元数据

- `id` 全局唯一，与目录名一致。
- `status`：`stub` | `draft` | `ready`。
- `dimension` / `group` 必须与路径一致。
- `updated` 使用 ISO 日期 `YYYY-MM-DD`。
- 不要把长文塞进 YAML；摘要控制在一两句。

## 4. 写作边界

- **摘要优先**：指向官方文档，不整章搬运。
- **可验证**：用法与演示中的命令应在合理环境下可执行（版本在文中注明）。
- **中立**：对比时写适用边界，避免无依据的绝对排名。
- **安全**：不收录用于未授权访问、恶意利用的「工具教程」；安全研究类条目保持防御与合法语境。

## 5. 演示（demo/）

- 优先最小可运行示例 / 实现样例；其次截图/录屏 + 步骤。
- 依赖使用常见包管理器；锁定或注明主版本。
- 不提交密钥、令牌、个人数据。
- 大媒体文件优先外链，并在 `demo/README.md` 写明来源。
- 演示是条目的一部分，不是独立站点功能。

## 6. 审阅清单（PR 自检）

- [ ] 路径落在 `languages` / `frameworks` / `domains` 之一
- [ ] `meta.yaml` 通过肉眼检查（必填齐全）
- [ ] 中文说明通顺；术语首次出现可附原文
- [ ] 外链非明显失效
- [ ] 未引入无关大文件或二进制垃圾
- [ ] 未引入网站工程或把正文挪到站点目录
